# R140 — Guidance arrives at its moment

Guidance arrives at its moment: each project's instructions file becomes short pointer lines to guides read when needed. The person, 2026-10-31: "we have a lot of instruction that is focused around, establishing a roadmap item or around establishing a vision. I don't want those instructions to be dumped into the context every turn When the turn may not have anything to do with creating a roadmap item or updating the vision. Is there a way that we can selectively deliver of the guidance only in the moment that the roadmap item is being updated or the vision is being updated? ... it's an all the time waste, When it's a some of the time instruction". Then: "Can we have those Claude and agent files basically the simple role lines, like 'if you're about to update the roadmap and don't remember what is in the X file read X file' ... And just get that down to as few tokens as possible". Agent's reading: CLAUDE.md/AGENTS.md is loaded at session start and re-read every step (about 4,000 tokens for colony's part; at the cached rate about 1% of each step, and every line competes for attention). The file becomes the few lines that hold every turn, plus one line per moment ("about to X and don't remember Y: read Y"), each guide a file in colony's folder, one copy for every project, re-read after a compaction because the pointer stays. Check: tokens of colony's part before and after; then a blind test on cheap Claude helpers: the same new-project, new-milestone, gate and hand-off moments with the full file and the pointer file, judged on whether the agent opens the right guide and on the quality of what it produces against the full version; ships only where the pointer version holds. Done 2026-10-31 (b8da584, 17c950c): colony's part of each instructions file went from about 3,600 tokens to about 1,270 (words x 1.35), with ten guides in guides/ behind one pointer line each. Blind test, three rounds, Sonnet agents judged pairwise by Opus (about $7.50): round 1 the full file won 10-5 (3 ties), every loss a sentence moved away from its moment (asking the foreseeable decisions, checks tracing to the criteria, commit each piece); after fixes the pointer version tied 5-5 on the hardest moments (laying out a roadmap, a decision for the person), matched finishing an item (3/3 checked, marked, committed), and read no guide on a routine edit (3/3), about 9k fewer input tokens per ordinary step; a gate or roadmap moment costs 14-22k more, reading two guides. Also found in both arms: gate defaults that would publish if the person skipped; the guides now say no default where skipping would publish, send or spend. Then the person, 2026-11-01: "I'm not in love that the new file isn't 100% as good in quality outcome" (reading: a tie on two moments isn't enough; it must hold everywhere, or the full file comes back). Rounds 4-6 (about $22): the same words in both arms, all inline against pointers, so only delivery differed; 6 runs per arm on all six moments, scored on outcome checks written first (design is in the scratchpad's r140-blind/r4/checks.md) and judged blind. Pointers won 19, inline 12, ties 5; never behind on any check; ahead on asking openly about a new project (6/6 vs 2/6) and on putting a roadmap's decisions as gates (5/6 vs 3/6); the drift request 3-3 with both arms 6/6 (named it, built nothing, asked). Finishing an item trailed 1-5 on the judge; 12 more pairs made it 8-9 pooled (p = 1.0, level). A line in roadmap.md's Finishing an item ("see whether finishing it shows something the vision needs that has no place on the roadmap, and bring that up") beat inline 10-2 (p = 0.039), naming the gap in 6/12 runs vs 0/12; added (f781a6d). Seen in both arms, not from the pointers: a turn ending on a question often skips colony needs-you (new project: inline 2/6, pointers 3/6), and small edits go uncommitted (rename: 0/6 and 1/6).
