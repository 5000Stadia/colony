Roadmap shapes that serve a project's shape. The person, 2026-10-20: "Is there a smart way that we can build a informative and dynamic roadmap area under the roadmap area that would allow for different types of roadmap focuses as as presented in this video https://youtu.be/b4YVHTqQPk8 ... But also, is there a way that we can make this section not just informative and visually clear in mapping to the user but allow more dynamic engagement from the user search that the shape of the roadmap really serves the goals of the project or am I getting to fine-grained in believing that there is different shapes of roadmaps that would better serve different shapes of projects". Agent's reading: not too fine-grained; one plan (ROADMAP.md) seen through views fitted to the project (sequence, now/next/later, by goal with gaps showing, timeline, parallel tracks), the agent proposing the view when it sets the vision, and the person steering from the map (move an item to Now, tap a goal to see what serves it, mark the goal that matters most), each reaching the agent as a note. The video's content was not readable here (only its title, Eleken's "How to Build a Product Roadmap in 6½ Simple Steps"). Asked: what in the video caught them, and whether the aim is seeing at a glance or steering. Proposed first step: the by-goal view. The person, 2026-10-20, later: "We also want to make sure we have comprehensive and helpful roadmap elements and views. They certainly need to lock in as the obvious best choice for the project. Test away if needed, research shapes that feel correct". Agent's reading: brought forward from Later on their word; the bar is that for each kind of project the view chosen is plainly the right one, so the set of shapes is researched (prior art, which shape fits which project), tried against their real projects (a product, research, a report, a picture book, an atlas, an engine), and the agent's pick of shape is blind-tested before it enters guidance. The video (read from its transcript): now/next/later, feature-by-date, goal-based, strategic, release; choose by audience and purpose; keep it living. The person, then: "Consider a range of shapes I dont cover. Self improvement, “your ceo of a new company with 10,000 dollers - go for it” kind if stuff". Agent's reading: the set must serve project kinds beyond their current ones (practice toward a capacity, a venture spending a budget on bets, pipelines, fixed-date countdowns, ongoing cadence), so the test cases include made-up projects of those kinds, not only theirs. The person, on the plan format: "we should consider our M# R# defaults we use, those are great but do they fit all these shapes? Does the novel have a roadmap 50 item? Seems like we could have sharper north star shapes if its not linier path work. And heck in the current shape there may be multiple lanes of roades categorically seperated". Agent's reading: the format itself is in question, not only the views: a part of a plan may be a sequence of milestones, a set of lanes (roads side by side, by category), chapters, bets or a cadence, under a north star sharper than a list (an outcome, its measure and its line); items keep a stable id for notes, gates and timers, but are shown by their own unit (Ch 7, Week 6, a bet's name), not as step R50. On the reviewers' points: accepted the first (shape each part); on a separate log of numbers: "the voice bench is only valid to make the decision then toss. We dont want to build harnessing and clunk that has no functional value", "I want clean and elegant not a bulky strap of tools as a ln effective worker otherwise has to juggle a library to just do a basic task". Agent's reading: no new commands for agents; a number lives in the plan where a part needs it, and its history comes from git, which already keeps every version; the general log is dropped; tools made for one decision are removed once it is made. On numbers in the plan (the reviewers' second point, trimmed to an optional measure line with its history from git), the person agreed and added: "further to prevent agent accounting about it encourage a automated mechanism handle it for example a programmatic word count on the novel or a mechanical rule that is established Ware a haiku model updates. The metrics that were established for each milestone completion or git hub push". Agent's reading: a measure says how it is taken, and the board takes it, never the working agent: a command run in the project (a word count, an eval script) where one exists, otherwise a small independent model (Haiku) reading the stated evidence; taken at each push and each milestone completed; the agent only declares the method once, where the person can see it. The person, on the mock-ups (Bookflow, holo-emitter, quality-lab, a $10k venture, a half marathon, each today's checklist against shaped views): "all of them seem functional. And I trust that whatever is on deck and the user is talking about is probably going to have focus. But what the entire pass forward looks like, and is smartest to do may not necessarily be universally a checklist. But at its worst to checklist is still pretty handy. Bring up the items put it in the order that makes less sense and keep on trucking. There seems to be notable value in the other shapes as well." Agent's reading: no shape is obviously wrong, so no rule for choosing one: kinds are tools an agent may use, the checklist stays the default and the fallback; focus comes from what is on deck and what the person is talking about, so the page leads with that; build the other shapes for their value, the agent picking ("most sense" read for "less sense"). On measures, the person: "It needs to make sure the metric its tracking is rooted in a meaningful element of the vision. For planning for a marathon, getting comfortable with more and more miles jogged in one day is meaningful. The number of tests software does before being pushed as a metric of quality is silly." Agent's reading: a measure shows the vision coming true, never activity; said so, with their two examples, in the line agents are told; on judged measures, a cheap separate model applies the method the agent wrote ("Oh for basic accounting totally").
