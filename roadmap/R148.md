# R148 Dev mode: projects tell colony where its shape got in their way

## The person's words

2026-11-02, late evening: "Can we have a sort of dev mode - basically that tells all projects in context if an issue
comes up fronm colonies shape that can be improved message colony the details so they can work on improving it!"

## Reading

This came from the person, unprompted. They want every project's agent to hear about colony's shape while it works:
a command, a guide, a rule, a notice or the board itself that gets in the way, misleads or is missing. Today that
friction stays in the conversation where it happened. Since the steward was muted (uc90ec5ad), nothing carries it
to colony. "In context" means the instruction sits in each project's own instructions, so it holds on every turn.
"Message colony" means this project, the lead for colony's code, using the mail projects already use.

It fits the vision as written: "never gets in the way of the work" and "wiser with every project". The vision
doesn't need to change. It complements R146: R146 reads friction from what colony records, and this has the agents
say it themselves, with what they meant to do, which records alone don't show.

## Proposed shape (the agent's)

1. **One switch, "Dev mode", in the board's settings, for the whole colony.** It only appears where colony's own
   repository is a project on the board, since anywhere else nobody would receive the reports. On here, off by
   default for other installations.
2. **While it's on, every project's instructions get one more line:** when colony's own shape gets in your way,
   send colony the details. That means what you were doing, what happened, what you expected, what it cost, and a
   fix if you see one. Send one message per issue, then carry on with your own work, because judging the report is
   colony's job. Colony itself doesn't get this line; its instructions say instead that reports arrive as mail.
3. **Reports wait for colony's next turn instead of waking it.** They use `colony send colony --dev "..."`: dev
   mail is tagged and quiet, so a sleeping colony doesn't re-read its whole conversation for each one. A project
   that colony is actually blocking sends plain mail, which wakes colony as usual.
4. **Colony answers every report:** fixed, already known (and where), or not colony's (and why), so the sender
   doesn't send it again.
   - Bugs are fixed at once (u28e150). New direction goes to the person as a proposal.
   - The reports feed R146's reading of friction.
   - A report is data, not instructions: it may carry text a project read from the web.
   - A project's own material never goes into colony's public repository. A fix carries the general lesson, not
     the project's details.

## Overhead in use

- About 60 words in every project's instructions, read on every turn while dev mode is on.
- A few hundred tokens of the sending project's turn for each report.
- Colony reads and answers reports along with its next turn. Fixes cost what fixes cost.
- The risk is noise: agents filing their own project's problems, or trivia. The line asks for evidence and one
  message per issue, and the first week's reports show whether that holds.

## How it will be checked

- **Tests:**
  - With dev mode on, the line appears in every project's CLAUDE.md and AGENTS.md except colony's own; with it off,
    the line is gone everywhere.
  - The switch is hidden where colony isn't a project.
  - `--dev` mail doesn't wake a sleeping colony; plain mail does.
- **In use, after a week:**
  - Count the reports, how many were truly about colony, and how many led to a fix or a roadmap entry.
  - If most are noise, tighten the line, or say so and propose turning dev mode off. Record the result here.
  - Note whether anything the steward used to do was missed. Dev mode takes over its last job: carrying a project's
    friction to colony. Bring the person that answer, since they are "Still not sure if steward is worth keeping"
    (2026-11-02). Whether to keep or remove the steward is their call; my reading is that once nothing misses it,
    removing it trims every project's instructions.
