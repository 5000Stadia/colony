# R157 A commit chained to a piped test run is turned back

## Where it comes from

The research project's list of eleven lines (roadmap/R131.md) had one with a record of harm. When a test run is read
through a pipe (`run tests 2>&1 | tail -5 && git commit …`), the shell reports the reader's exit status, not the
tests', so the commit goes ahead whether they passed or not. Counted in the transcripts before building: 165 such
commands in ten project folders (the research project counted 135 in nine with a stricter pattern and read each
whose output showed a failure: at least 11 committed, restarted or sent over a failing run, 7 of them in colony).
The person chose to build only this (gate g1b590263, answered Nov 11).

## Shape

- One more test in the check colony already runs before every shell command (colony/waiting.py, R137's hook, both
  programs). No words in any agent's context until the moment it applies.
- Turned back: a test runner whose output goes through a pipe to a reader, with a `git commit` later in the same
  command, where the command has neither `pipefail` nor `PIPESTATUS`.
- Let through: tests run alone; tests redirected to a file and gated on their own status; `set -o pipefail`; a
  check of `PIPESTATUS`; a collect-only run; a heredoc's body; anything in doubt.
- The refusal says the free way: run the tests alone and commit on their own exit status, or put
  `set -o pipefail;` first.
- Only the commit is covered, as asked. A restart or a send chained the same way is not.

## How it is checked

1. Unit cases for both programs: forms it must turn back and forms it must let through, including
   `2>&1 | tail && git commit` (the case my first count missed).
2. Run over every shell command in the transcripts (no model run): it turns back the commands the corrected count
   found, and what else it turns back is read by hand; wrong refusals are fixed or counted.
3. The full suite passes before the board restarts.

## What was built, and the check's result

- `commits_unread(command)` in colony/waiting.py, beside the clock-wait check; the hook's refusal text says the
  free way. It holds in the background too, where a wait is free and a commit over a failure is not.
- Unit cases: nine forms turned back, twelve let through, for both programs (tests/test_context.py).
- Over all 152,001 shell commands in the transcripts: 162 turned back, every one a command the corrected count had
  found, and none outside it. The count's other 4 were collect-only runs, which have no result to lose, so the true
  figure is 161 at the time of the count, not 165.
- One wrong refusal seen while building: a command that only quoted such a line as a string to try the check. Its
  cost is one retry; left as it is.
- The suite: 1,187 tests pass.
