# R168 — Week limits for the whole colony, per program

A limit on a program's week that every project keeps to, with a project's own in its place where it has one. Past
a program's limit no project starts new work on that program; each carries on with the other.

## Where it came from

On 2026-11-15 the person told one project to start nothing more on Codex, so that Codex stayed free for their own
use. That project kept to it. Another project, which had no limit and never heard the direction, ran twelve Codex
jobs overnight and took Codex's week from about 80% to 100% (read from Codex's own session records, by the folder
each session worked in). A direction about a program's week, given in one project, bound only that project: colony
had no place to say it once.

The week pause as it was built (a project's own setting, one number) had a second fault that night: it counted
every program against the whole project, so Codex passing the number stopped the project's Claude work too, against
what the person had said. Their answer (gate gfb778909): a colony-wide limit, and each project able to have its own
limits, project by project, with no tiers or categories.

## What changed

- `week_pause` is now also a colony setting (Settings, under Safe pause; `colony settings week_pause`): a number for
  every program, or one per program (`claude=70, codex=85`). None is set until the person sets one.
- A project's own `week_pause` takes colony's place for the programs it names; `off` is none for that project;
  blank is colony's again. A number saved before reads as every program's.
- A program past its limit stops new work on that program only. A project that runs on that program winds down and
  waits for the person, as the week pause did. A project on another program is not paused: each turn, while the
  limit holds, its agent hears that nothing new starts on the program past its limit.

## How it was checked (2026-11-16)

- Tests (tests.test_board, the two week-limit tests): another program past its limit pauses nothing and the agent's
  line names it, with mail still starting the project; its own program past the limit pauses it and tells it once;
  colony's limit holds with none of the project's own; a project's own takes its place per program, lower or
  higher, or off; a number saved before still reads; a limit that can't be read is refused; both fields show.
  The earlier test asserted the opposite on one point (another program's week pausing the project) and was changed
  with the behaviour. The whole suite passes.

## Open

- What a project's own number counts: its own use of the week, or the whole week's reading as now (gate gca2f5233).
- The line reaches an agent at the start of a turn, not in the middle of one; nothing stops a command that starts
  the other program.
