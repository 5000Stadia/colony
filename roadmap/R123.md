# R123 — The player as the unheard line

The player as the unheard line (option B of the fresh-eyes review, design/player-review/): a headphones pill counts the replies you haven't heard; tapped, it opens the line, with filter chips (All · 5, colony · 2, Bookflow · 3) that filter and never start anything, Play all, a tap on a row to start there, and Auto as one switch that keeps the line going. Playing shows "1 of 5", pause and skip, and folds back into the pill when the line runs out. Gone: ■ (which also turned Auto off and dropped All, silently, and sat 50 px above the agent's own ■), the inline Auto and its menu, and Read from and Across, which merge into the chips. The modes, speed and voices sit one row down. The person, 2026-10-28, of the controls: "I am too entrenched to make a good decision about it, but I feel like the design decisions I've made over time to visualize the Auto and the controls surrounding play and Auto play are not as clear or intuitive as I originally intended"; of B: "I think I like B, can't hurt to try, we can go back if need be, looks clean/smart". My reading: try it as the player, keep today's code in git to go back to, and judge it in their own use. It stands on an unheard count they can trust, so the per-device heard memory is checked first. The person, after the second view: "if the user hears or reads something in all, it should be eliminated from the valid queue of the individual project that it is from in case the user goes to that project and then listens project specific. Vice versa if elements are Auto played from a specific project and then the user switches to all projects. It should be effectively read." My reading: one heard mark per reply, which All, each project's own queue and every device read alike. A reply heard or read anywhere is gone from every line it was in (point 1 of consultation c1c9d7dc8). The check: hear a reply in All, open its project, and it isn't queued there; the same the other way round. Then, the same day, while it was being built: "I also would like when text and audio are both playing that the specific word that is being read by the audio is visible on the screen. One way to do this as if the sentence that is about to be read, continues off the visible page then the page should adjust such that the first visible sentence in the viewer window becomes that sentence that is about to be read." and "Or some other more elegant approach I just thought that would be a smart move". Agent's reading: their page turn, kept as they describe it: the page moves only when the sentence about to be heard would run off, and that sentence becomes the first one in view. This moves the page least, and a page that keeps scrolling is hard to read along with. Added: a soft mark on the sentence being heard, so the eye finds it after each turn. The timing is estimated within each clip, since the voice gives no word times. Check: a reply over three screens tall in Audio + text, with the sentence being heard always in view. Then two more from the phone the same evening: "I think when I interrupt it, maybe when I'm sending a message or something like that it goes to pause but then it doesn't automatically resume sometimes and I have to hit play again", and "sometimes when I lock my phone, the audio keeps playing which is great ... anything you can do to support that kind of usage for either iOS or android is wonderful". Agent's reading: the first is a bug. Dictation takes the phone's audio, so the pause counts as the phone's, and the dictation hold that would take it up again never starts. Fixed in the rebuild: Send resumes it from the tap itself, and a refused play says "tap to resume". The second makes the locked screen first-class on both phones. The silence between replies holds for 2 hours while Auto is on, not 20 minutes. There's no gap between clips. The lock screen shows and controls what plays, and each stop the phone makes is logged, so the live trial shows what still cuts it off. Built and live 2026-10-28 (71ab5ab): the line kept on the board (each project's .board/line.jsonl and heard.jsonl, starting empty when it went live), the pill and the line sheet, Auto across every project for new arrivals only, "tap to resume", the toggle under each reply, follow-along with the sentence marked, the dictation hold, locked play held 2 hours, and the pill stepping aside from boxes and buttons. ⏭ now skips the whole reply.
