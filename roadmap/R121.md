Colony comes back by itself after the machine restarts, and the person can restart it with the projects parked first. The person, 2026-10-28: "because of the nature of colony if the system is restarted, I want colony to automatically load", "And all of its Tailscale and other continuation elements of projects to continue, which is probably just a gentle message nudge to the project", and "an option to restart from a colony function, not from an agent, but token free, which does a bit of a round Robin request to notify projects, and to ask projects to inform a response that restart is OK. So the projects have a chance to park their stuff. Also, with a further notification that if it doesn't get parked within the next hour that it will force a restart. Then when the function gets an all clear then the system can restart. And if it doesn't get an all clear, it restarts in an hour anyways." My reading: a systemd user service starts the board at boot (linger is on; Tailscale is a system service already); each console that was running comes back in its own conversation, one a minute with memory to spare, and those mid-work are told once to carry on; colony reboot (or Settings > This machine) asks each project at work in turn to park and answer with colony noted, counts one idle with nothing running as clear, and restarts once all are clear or at the hour. Check: the tests for each; then the person's own restart tomorrow, the board and consoles back with no one at the keyboard.
