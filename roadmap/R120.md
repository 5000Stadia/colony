My reading: once the new disk and memory speed are in, decide each of these again on what the machine then has, nothing built before. (1) Swap: grow /swap.img on the new SSD (16 GB suggested), or zram, or both; empty today's full swap. (2) A-XMP: stable at 3400, or drop to 3200 / run memtest86+ once. (3) Colony starting itself at boot as a user service (linger is already on). (4) The reload guard's 2 GB of free memory (console.room), against the new swap. (5) Memory per project on the board (consoles' scopes, ended ones too), a machine line with what runs outside colony, and a low-memory warning naming the biggest users; consoles yielding to the board in a crunch (raising their oom_score_adj above its 200). (6) The Blender MCP in the user config, started by every Claude Code session (14 copies, about 550 MB with Blender closed); the person left it as is for now. Context: the 2026-10-28 crash (memory out at 10:01, the board killed at 4 GB) and the fixes in ca1580a. Added 2026-10-28 from the Linux research (research library re1b5116b), asked by the person: "If you had to determine the best flavor of linux for colony to maximize performance and capability out of the box what would you pick". Verdict: stay on Ubuntu, with no switch. The gain any other distribution offers here is memory defaults, which Ubuntu gets with a setting. Every candidate runs the same scheduler, and nothing measured favours another for many mostly idle agents. Ubuntu 26.04 LTS is the Quickstart's target. For this machine, in order: (a) zswap on (`zswap.enabled=1 zswap.compressor=zstd` on the kernel command line; measured here: off, lzo), so what is swapped stays compressed in memory; (b) swap grown on the new SSD, as (1) says; (c) colony's part, measured here: every console runs in one tmux server, inside one GNOME Terminal scope, and user@1000.service has systemd-oomd set to kill at 50% memory pressure. One kill there would end every console at once, so the consoles need their own scope, or one oomd avoids, with Chrome and the voice limited first; (d) optional, upgrading to 26.04 right after the clone, the old disk the way back. Its cost: Python moves from 3.12 to 3.14, so every Python environment made on 3.12 is remade (colony's voice, projects' .venv folders).
